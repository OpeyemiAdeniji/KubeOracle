# Running KubeSift in production

## Pick a mode

| | Single replica (default) | High availability |
|---|---|---|
| Storage | SQLite file on a PersistentVolume | PostgreSQL (`database.url`) |
| Replicas | 1 (Recreate rollout, ~1 minute gap on restarts) | 2+ (rolling updates, PodDisruptionBudget, spread across nodes) |
| Background scans | the one pod | the Lease holder only; another replica takes over within ~30s |
| Good for | most teams, one cluster | shared platform service, on-call tooling that must stay up |

```bash
# High availability
helm install kubesift oci://ghcr.io/opeyemiadeniji/charts/kubesift -n kubesift --create-namespace \
  --set replicaCount=2 \
  --set database.url='postgresql://kubesift:PASSWORD@postgres.db:5432/kubesift'
```

Use a managed PostgreSQL (RDS, Cloud SQL, Azure Database) or an operator such as CloudNativePG. Tables are
created on startup. To keep the URL out of Helm values, put it in your own Secret under `database-url` and
set `existingSecret=<name>` and `database.fromExistingSecret=true`.

How the replicas coordinate:
- **Leader election:** a `coordination.k8s.io` Lease named `kubesift-scanner`. Only its holder runs
  background scans and sends Slack/Teams notifications.
- **Alert dedupe:** Alertmanager can send to any replica. The "investigated recently" claim lives in the
  database, so each namespace is investigated once per `alert_cooldown`.
- **API and MCP requests:** stateless; any replica can answer.

## Access and authentication

- One bearer token (`KUBESIFT_API_TOKEN`, generated by the chart) protects the dashboard API, the
  Alertmanager webhook and the MCP endpoint at `/mcp`.
- **Single sign-on:** put the Service behind oauth2-proxy, or your ingress controller's OIDC support (Okta,
  Google, Entra ID), and keep the token for machine clients (Alertmanager, CI, AI assistants).
- `/healthz`, `/readyz` and `/metrics` are unauthenticated and expose no cluster data beyond finding counts.

## AI assistants against the shared service

```bash
claude mcp add --transport http kubesift https://kubesift.example.com/mcp \
  --header "Authorization: Bearer $KUBESIFT_TOKEN"
```

Other clients take the same URL and header (see [mcp.md](mcp.md)).

## Sizing

Measured on a synthetic cluster with 5,000 pods, 1,000 Deployments and 1,000 Services: one full analysis
takes about 2-3 seconds. Memory stays small because Secret and ConfigMap values are dropped at read time.
The default requests (50m CPU, 128Mi memory, 512Mi limit) fit clusters up to a few thousand pods. Raise the
memory limit for bigger clusters, or scope background scans with `scan.namespace`.

API load on the Kubernetes control plane:
- Snapshots are cached for `cache_ttl` seconds (default 20), so bursts of dashboard requests read the cluster once.
- Background scans run every `scan.interval` seconds (default 300) and use paginated list calls.

## Data and retention

- Investigations are kept for `history_days` (default 30). Team notes and the fix audit log are kept until you
  delete them.
- What leaves the cluster: only what you send to your LLM provider (see [configuration.md](configuration.md#llm)).
  Use `llm.provider=ollama` (or none) to keep everything in your network.

## Upgrades

`helm upgrade` rolls replicas one at a time in HA mode; database tables are created or extended
automatically. Single-replica mode restarts the pod, and history is kept on the volume.
