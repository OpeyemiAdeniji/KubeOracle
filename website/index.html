How it works

    
From "something's down" to the fix, in one command.

    
Most tools tell you a pod is crashing. KubeSift tells you which deploy broke it, what changed, and how to undo it.


    

      

        01
        
Read the cluster

        
One parallel read through the Kubernetes API: workloads, events, nodes, networking, storage, Helm releases,
          Argo CD apps and the logs of failing containers. Secrets are reduced to key names on read.

      

      

        02
        
Prove what's wrong

        
71 deterministic checks turn raw state into findings with evidence copied from the cluster — exit codes,
          scheduler reasons, missing keys, the log line that names the missing env var.

      

      

        03
        
Find what changed

        
Rollout diffs (image, env, resources, probes), ConfigMap edits, Helm upgrades and Argo CD syncs are linked to
          the failures that followed them, with the exact rollback command.

      

      

        04
        
Explain it, carefully

        
Findings become incidents with causes before symptoms. Add Claude, OpenAI or a local model for a written
          explanation — every claim must cite real evidence, or its confidence is capped.

Before, during and after

    
Covers the whole incident, not just the fire.

    
Most incidents follow a change. So KubeSift checks changes before they ship, explains failures when they happen, and writes up what happened afterwards.

    

      
Preflight
Before deploy, check the change against the live cluster: missing Secrets, pods that won't fit, a memory limit below what the app uses today, env vars the running version needs, webhook rejections.

      
Diagnose
When something breaks: the cause, the change that triggered it, and the rollback — in your terminal, AI assistant, dashboard or Slack.

      
Time travel
Compare the cluster now with an hour ago. See every image, config key, replica count and node that changed, even ones Kubernetes doesn't record.

      
Postmortem
One command drafts a blameless postmortem: impact, timeline, root cause, triggering change and action items, built from cluster evidence.

      
On-call in Slack
/sift why checkout in a channel. Answers with evidence and a "Roll back (dry run)" button. Applying needs your approval and permission.

      
Fire drills
kubesift drill start crashloop safely breaks a training namespace so new engineers practise on realistic failures.

      
Team knowledge
Record what fixed an incident once; it appears next to the same problem later. Export a pack and share it with other teams.

      
Upgrades & cost
Blockers for the next Kubernetes version, and right-sizing from real usage — the incidents and bills you avoid.

    

  







  

    
Four ways in

    
Use it where you already work.

    
One engine behind every entry point. Same checks, same evidence, same answers.

    

      

        01 · Terminal
        
CLI & kubectl plugin

        
Diagnose, ask questions in plain English, see recent changes, audit for production, check upgrades and cost.

        
$ kubectl sift diagnose -n shop -v
$ kubectl sift ask "why is checkout failing?"
$ kubectl sift changes --since 2h
$ kubectl sift upgrade-check --target 1.36

      

      

        02 · AI assistants
        
MCP server

        
Give Claude Code, Cursor or VS Code structured cluster evidence. Your assistant reasons; KubeSift supplies facts.

        
$ claude mcp add kubesift -- kubesift mcp
# or the shared, token-protected endpoint
https://kubesift.your-co.com/mcp

      

      

        03 · In the cluster
        
Dashboard, API & alerts

        
Helm chart with a web dashboard, REST API, Alertmanager receiver and background scans that post the diagnosis
          to Slack or Teams before anyone opens a laptop.

        
$ helm install kubesift \
    oci://ghcr.io/opeyemiadeniji/charts/kubesift \
    --set notifications.slackWebhookUrl=$SLACK

      

      

        04 · CI
        
Stop it before it ships

        
Lint manifests, Helm charts and Kustomize output on every pull request. Results land in GitHub code scanning (SARIF).

        
# .github/workflows/k8s.yml
- uses: OpeyemiAdeniji/KubeSift@v2
  with:
    paths: k8s/
    target-version: "1.36"

What it catches

    
71 checks built from real incidents.

    
Each one says what is wrong in plain words, shows the evidence, and gives the fix.

    

      
Workloads
Crash loops explained by exit code and logs, OOM kills with a suggested limit, rollouts past their deadline, failing Jobs and CronJobs.

      
Images & config
Missing ConfigMaps, Secrets and keys; bad image tags; Docker Hub rate limits; images built for the wrong CPU architecture.

      
Network & DNS
Services with no endpoints (and the label typo why), wrong target ports, broken Ingress and Gateway routes, NetworkPolicies that block DNS.

      
Nodes & scheduling
NotReady and pressured nodes, the scheduler's real reason a pod is Pending, full clusters, cordoned nodes left behind.

      
Platform
Admission webhooks that block every deploy, pod IP exhaustion, Pod Security rejections, expired certificates, CoreDNS down.

      
Upgrades
Removed APIs in manifests and Helm releases, PDBs that hang node drains, retired ingress-nginx, containerd 1.x, cgroup v1, kubelet skew.

      
Cost
Over-requested CPU and memory with right-sizing from real usage, idle GPUs, unused volumes, load balancers with no backends.

      
Security & reliability
Privileged containers, secrets in plain env vars, cluster-admin service accounts, single replicas, missing probes and limits.

Built to be trusted with production

    
Read-only by default. Evidence, always.

    

      
◎
AI is optional
Every finding comes from deterministic checks. Bring Claude, OpenAI, OpenRouter or a local Ollama model — or none at all.

      
⛨
Your secrets stay yours
Secret and ConfigMap values are dropped at read time. Tokens, passwords and keys are redacted from logs before anything is stored or sent.

      
↺
Guarded fixes
Restart, rollback and scale show a plan, run a server-side dry run, ask before changing anything, and write an audit log.

      
⇄
Highly available
Run two or more replicas on PostgreSQL. A Kubernetes Lease elects one scanner; failover takes seconds.

      
✓
Signed releases
Container images and Helm charts are signed with cosign and ship an SBOM and build provenance.

      
⌁
Tested on real clusters
Every change breaks a kind cluster in ten ways and checks each failure is caught, then installs the chart in both modes.
